# デモ動画

Web アプリを Playwright で操作し、字幕を焼き込んだ動画をセクションごとに録画して mp4 にする。同梱のスクリプトはこの SKILL.md と同じフォルダの `scripts/` にある（以下 `$S`）。

動画は Mac では `~/Movies/claude-demos/<名前>-<YYYYMMDD>/`、Windows では `$HOME/Videos/claude-demos/<名前>-<YYYYMMDD>/`（以下 `$OUT`）に作る。シナリオもここに `scenario.mjs` として置き、撮り直しに使う。

Windows には試験的に対応している（動かして確かめていない）。Windows で止まったら、出た文をそのままユーザーに伝える。

## 手順

### 1. 道具をそろえる

Mac では `bash $S/setup.sh`、Windows では `powershell -ExecutionPolicy Bypass -File $S/setup.ps1` を流す。Node.js・Playwright・ffmpeg は、足りなければ `~/.cache/demo-video/` に自動で入る。ユーザーに何かを入れてもらう必要はない。

- 最後に「準備できました」と出れば終わり。`node:` の行に出たパスを、以下の `node` の代わりに使う。
- `chrome:` で止まったら、https://www.google.com/chrome/ から Google Chrome を入れてもらい、入れ終わったらもう一度流す。
- それ以外で止まったら、出た文をユーザーに伝えて止まる。

録画する URL を `curl -s -o /dev/null -m 10 -w '%{http_code}'`（Windows の PowerShell では `curl.exe`）で開き、どれも応答が返ることを確かめる。タイムアウトするときは、VPN などの接続をユーザーに確かめてもらう。

### 2. ログインする

サイトごとにプロファイル名を決める（シナリオの `profile` に使う）。ログインした状態はプロファイルに残り、ほかのセクション・`probe.mjs`・撮り直しでもそのまま使える。ログインのしかたはサイトに合わせて選ぶ。

- **ログインが要らないサイト**: プロファイル名だけ決めて、手順 3 に進む。
- **パスワードで入れるサイト**: メールアドレスとパスワードをチャットで聞く。値はファイル・ログ・字幕に残さず、コマンドに渡すときは環境変数にする。ログイン画面で入力して送るだけのシナリオを `$OUT/login-scenario.mjs` に書き、`--mode rehearsal --out $OUT/login` で流してログインした状態を残す。ログインの場面を動画で見せたいときは、同じ操作を本番のシナリオにもセクションとして入れる。
- **自動化できないログイン**（Google・SSO・多要素認証など）: `node $S/login.mjs --profile <名前> --url <ログイン画面>` を背景で流し、開いた Chrome でログインして窓を閉じてもらう。

終わりの目安: `node $S/probe.mjs --profile <名前> <ログイン後の URL>` が、ログイン画面に飛ばされずに中身を返す。途中でログインが切れたら、同じやり方でもう一度ログインする。

### 3. 画面を下見する

見せる画面ごとに `probe.mjs` で作り（ボタン名・見出し・入力欄）を出し、ロケータを決める。見た目も要るときは `--screenshot <保存先の頭>` で全体の画像を残す。画面を移る操作は、データを変えない範囲で `probe.mjs` やリハーサルで確かめる。

### 4. シナリオを書く

`$OUT/scenario.mjs` を書く。形と使える操作は [`reference.md`](reference.md)、例は [`example-scenario.mjs`](example-scenario.mjs)。

- 1セクションは、見る人が1回で追える画面のまとまり（目安 30 秒〜2 分半）にする。
- 字幕は、何を見せているか（`cap`）と、なぜそうなっているか（`sub`）の2段で書く。書いたら字幕の文だけを1行ずつ並べて yomiyasu に渡し、直った文をシナリオに戻す。完了報告などの体裁は要らない。
- データを変えた後の画面は下見できない。その画面について言い切る字幕（「かっこの中は部署です」など）は、下見で見た例だけを根拠にせず、手順 8 で録画と照らす。
- データを変える操作（投稿・保存・送信・削除・ステータス変更など）は、その直前に `r.mutation("何をするか")` を置く。
- ユーザーが色を言ったら、シナリオの `theme` に書く。タイトル画面の背景と章名の札がその色になり、文字は白か黒の読みやすいほうに自動で決まる。書かなければ緑になる。

### 5. ユーザーに確かめる（必須）

次の5つを見出しにした文章をチャットに貼り、返事を待つ。OK をもらうまで、リハーサルも録画も流さない（`probe.mjs` は流してよい）。共有の環境では、リハーサルでも確認の前だと止められることがある。

- セクションの一覧と、それぞれの操作の流れ
- 字幕の全文
- データを変える操作の一覧と、変わるデータ・送られるメールとその宛先（なければ「なし」と書く）
- 撮り直したときに増えるデータ（同じ操作をもう一度行うことになる）
- テーマカラー（指定がなければ「既定の緑」と書き、変えたい色があれば言ってもらう）

### 6. リハーサルする

`node $S/run.mjs $OUT/scenario.mjs --mode rehearsal --out $OUT` を流す。録画はせず、各セクションを最初の `r.mutation` の手前まで動かす。

終わりの目安: すべてのセクションが `ok` か `stopped` になる。`error` のセクションは `$OUT/rehearsal/` の画像を見て直し、もう一度流す。

### 7. 録画する

`node $S/run.mjs $OUT/scenario.mjs --mode record --out $OUT` を流す。セクションごとの `NN_<タイトル>.mp4` と、つないだ `all.mp4` ができる。`error` のセクションがあれば、直して `--only <番号>` で撮り直す。

### 8. 録画を確かめる

`$OUT/check/NN.png`（各セクションから等間隔に 12 枚抜いた一覧）を全部見る。

- 字幕が、見せたい要素を隠していない。隠していれば、その `say` に `top: true` を付ける。
- 字幕と画面が合っている。画面が移る前に次の字幕が出ている、または前の字幕が残っているときは、`say` の位置を入れ替える。
- 見せたい要素が画面に入っている。
- 字幕の説明が、データを変えた後の画面とも合っている。

直したセクションだけを `--only` で撮り直し、もう一度一覧を見る。撮り直しでデータを変える操作がまた行われるときは、手順 5 と同じく先にユーザーに確かめる。

終わりの目安: すべての一覧で、上の4つに当てはまる所がない。

### 9. 渡す

ユーザーに次を伝える。

- `$OUT` と、セクションごとのファイル名・長さ
- `$OUT/report.json` の `mutations`（録画で変えたデータの一覧）。消すことはしない。
